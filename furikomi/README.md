Dropbox の `※請求書※/買掛/<期>/<YYMM月>/<店舗>/` に請求書が入ったら、
Google スプレッドシートの振込一覧へ自動で転記する仕組み。

`claude/dropbox-invoice-pdf-list-9pls7h`）とは別系統。あちらは月次の損益、

## スプレッドシートの構造（2026-08-25 調査）

- 期ごとに1ファイル。**月ごとに1タブ**（「9月分」「10月」…「8月」）。
- タブの月 = 請求書フォルダの月（**同月**）。検証: 2607月フォルダの
  ヴィーナスダイニング¥212,703・ミノアカ¥302,500・佐倉クレーン学校¥37,000 が
  いずれも7月タブにある。
- 列は店舗ごとに「振込先・金額」のペア:
  業務課 / 鳥害対策課 / 神栖横丁 / もも焼きJAPAN / タコハイ / りゅうちゃん /
  ハナ / 焼きたて屋 / 十三里屋（+ 総合計列）
- 行は支払い方法のセクション:
  1. 月末にPayPay銀行から支払う分
  2. 10日にPayPay銀行から振り込む分
  3. 小見川支店から支払う
  4. 自動引落分
- 金額は**税込**（請求書の「今回御請求額」）。
- 定番の取引先は行が雛形として毎月並んでいて、金額セルだけ空いている。

## セクションの決め方

1. その取引先の行が既にタブにあれば、そのセクション（雛形行）に入れる。
2. 新規の取引先は請求書の支払期日から:
   月末期限→「月末」、10日期限→「10日」、
   ファイル名や書面に「振替」「引落」→「自動引落分」。
3. 判断できなければ**保留リストへ**（推測で埋めない。pl/ と同じ大原則）。

## 書き込みルール（transcribe.py が強制する）

- 既に入っている値は**絶対に上書きしない**。
- 同じ取引先・同じ金額が既にある → 転記済みとしてスキップ。
- 取引先の行があって金額が空 → 金額だけ入れる。
- 行が無い → セクションの空き行に 振込先+金額 を新規記入。
- 迷ったら保留（exit code 2）にして利用者に報告。

## 定期チェックの手順（Routineが起きたらやること）

1. `mcp Dropbox list_folder` で `買掛/21期`（2607月以降の月フォルダ）と
   `買掛/22期` を再帰リスト。新しい月フォルダも自動で対象に入る。
2. `furikomi/ledger.json` の baseline / processed に無い file_id を抽出。
   （**file_id で照合**。支払い後に `支払い済/` へ移動されてもIDは同じなので
   二重転記にならない）
3. 新ファイルなし → 何もせず終了（コミットも報告もしない）。
4. 新ファイルあり → 各ファイルを `mcp Dropbox fetch` でテキスト抽出
   （スキャンPDF等で失敗したら download_link + curl で落として目視で読む）。
   請求書から 取引先名（シートの短い表記に寄せる）・税込請求額・支払期日 を抜く。
   請求書でないもの（銀行明細CSV・ENEOS等のPL用データ）は skip として台帳に記録。
5. entries.json を作り、鍵を用意して転記:

        # 鍵の受け渡し（pl/push.py と同じ経路。会話ログに鍵を通さない）
        # Dropbox download_link で /※請求書※/sa-key.json.json の一時URLを発行し
        curl -sSL -o /tmp/sa.json "<一時URL>"
        GOOGLE_SA_KEY_FILE=/tmp/sa.json python3 furikomi/transcribe.py entries.json --dry-run
        # dry-run の結果を確認してから本実行
        GOOGLE_SA_KEY_FILE=/tmp/sa.json python3 furikomi/transcribe.py entries.json
        rm -f /tmp/sa.json

6. 結果を `ledger.json` の processed に記録
   （file_id → path, vendor, amount, month, cells, action）。
   保留になったものは `hold` として理由も書く。
7. `git add furikomi/ && git commit && git push -u origin claude/invoice-auto-transfer-1wdzx5`
8. 保留が出たときだけ利用者に報告する。全部きれいに入ったら黙ってコミットのみ。

依存: `pip install google-api-python-client google-auth`（コンテナに無ければ入れる）

## 運用メモ・ハマりどころ

- **月フォルダの請求書は後から増える**（2607月は23→60ファイルに増えた実績）。
  だから毎回全ファイルをリストして台帳と差分を取る。
- 支払いが済むとファイルは各店舗の `支払い済/` サブフォルダへ移動される。
  file_id 照合なので影響なし。
- ファイル名の「〜8月末」「〜振替」「〜済」は支払い方法のヒント。
  「済」は支払い済みでも転記自体は行う（一覧は支払いの記録でもあるため）。
  ただし迷ったら保留。
- 本部フォルダでも中身が他店舗宛のことがある（pl/README.md ハマりどころ6・9）。
  請求書の宛名・内容を見て列を決め、フォルダ名だけで機械的に決めない。
- 1枚の請求書に複数店舗ぶんが載るもの（日本食研「ハナ・もも焼き・タコハイ」等）は
  店舗ごとに金額を分けて複数エントリにする。内訳が読めなければ保留。
- 2606月以前への後入れは対象外（支払いが締まっているため）。必要なら手で。

## 台帳（ledger.json）

- `baseline`: 2026-08-25 導入時点で既にあったファイル。利用者が手で転記済み
  とみなし、自動転記はしない（21期の7月タブまでは手入力で埋まっていた）。
- `processed`: 自動転記が処理したファイル。file_id → 結果。
