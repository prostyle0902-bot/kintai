# 請求書 → 振込一覧 自動転記

Dropbox の `※請求書※/買掛/<期>/<YYMM月>/<店舗>/` に請求書が入ったら、
Google スプレッドシートの振込一覧へ自動で転記する仕組み。

- 21期_振込一覧: `1CF5lIjrs3N4fTrVHa6BzSZtvbb0fmMWGZC3m8zn7LuM`
- 22期_振込一覧: `1d4s7XqlTb9xK-o3ujDd8PGiDMo23l5TzSg_wpl3DzRU`

2026-08-25 作成。損益計算書の自動転記（`pl/`、別ブランチ
`claude/dropbox-invoice-pdf-list-9pls7h`）とは別系統。あちらは月次の損益、
こちらは「今月誰にいくら払うか」の一覧。

## 動く仕組み

Claude のセッションに Routine（定期起床）が紐づいていて、
**毎日 10:00 / 12:00 / 15:00 JST** に起きて下の「定期チェックの手順」を実行する。
取り込みの実行主体は Claude（Dropbox・Drive へのアクセスはコネクタ経由のため、
GitHub Actions 等では動かせない）。

    Routine名: 振込一覧 請求書自動転記チェック
    trigger_id: trig_01Rt2X5vj3R4H1XtBpT4HhpV
    cron: 0 1,3,6 * * *（UTC。= 10:00 / 12:00 / 15:00 JST）

当初は2時間おき7回だったが、1日3回で足りると利用者が判断（2026-08-27）。

### ファイルが入った瞬間には転記できない

Dropbox のファイル追加を Claude に push する仕組み（webhook）が
このコネクタには無いため、**定期的に見に行く（ポーリング）しか手段がない**。
だから「フォルダに入れた瞬間」ではなく「次のチェック時刻」に転記される。
急ぎのときは、このセッションで「チェックして」と言えばその場で実行する。

## スプレッドシートの構造（2026-08-25 調査）

- 期ごとに1ファイル。**月ごとに1タブ**（「9月分」「10月」…「8月」）。
- タブの月 = 請求書フォルダの月（**同月**）。検証: 2607月フォルダの
  ヴィーナスダイニング¥212,703・ミノアカ¥302,500・佐倉クレーン学校¥37,000 が
  いずれも7月タブにある。
- 列は店舗ごとに「振込先・金額」のペア:
  業務課 / 鳥害対策課 / 神栖横丁 / もも焼きJAPAN / タコハイ / りゅうちゃん /
  ハナ / 焼きたて屋 / 十三里屋（+ 総合計列）
- 行は支払い方法のセクション:
  1. 月末にPayPay銀行から支払う分
  2. 10日にPayPay銀行から振り込む分
  3. 小見川支店から支払う
  4. 自動引落分
- 金額は**税込**。取り方は下の「請求書から取る金額」を参照。
- 定番の取引先は行が雛形として毎月並んでいて、金額セルだけ空いている。

## セクションの決め方

1. その取引先の行が既にタブにあれば、そのセクション（雛形行）に入れる。
2. 新規の取引先は請求書の支払期日から:
   月末期限→「月末」、10日期限→「10日」、
   ファイル名や書面に「振替」「引落」→「自動引落分」。
3. 判断できなければ**保留リストへ**（推測で埋めない。pl/ と同じ大原則）。

## 書き込みルール（transcribe.py が強制する）

- 既に入っている値は**絶対に上書きしない**。
- 同じ取引先・同じ金額が既にある → 転記済みとしてスキップ。
- 取引先の行があって金額が空 → 金額だけ入れる。
- 行が無い → セクションの空き行に 振込先+金額 を新規記入。
- 迷ったら保留（exit code 2）にして利用者に報告。

## 定期チェックの手順（Routineが起きたらやること）

1. `mcp Dropbox list_folder` で `買掛/21期`（2607月以降の月フォルダ）と
   `買掛/22期` を再帰リスト。新しい月フォルダも自動で対象に入る。
2. `furikomi/ledger.json` の baseline / processed に無い file_id を抽出。
   （**file_id で照合**。支払い後に `支払い済/` へ移動されてもIDは同じなので
   二重転記にならない）
3. 新ファイルなし → 何もせず終了（コミットも報告もしない）。
4. 新ファイルあり → 各ファイルを `mcp Dropbox fetch` でテキスト抽出
   （スキャンPDF等で失敗したら download_link + curl で落として目視で読む）。
   請求書から 取引先名（シートの短い表記に寄せる）・税込請求額・支払期日 を抜く。
   請求書でないもの（銀行明細CSV・ENEOS等のPL用データ）は skip として台帳に記録。
5. entries.json を作り、鍵を用意して転記:

        # 鍵の受け渡し（pl/push.py と同じ経路。会話ログに鍵を通さない）
        # Dropbox download_link で /※請求書※/sa-key.json.json の一時URLを発行し
        curl -sSL -o /tmp/sa.json "<一時URL>"
        GOOGLE_SA_KEY_FILE=/tmp/sa.json python3 furikomi/transcribe.py entries.json --dry-run
        # dry-run の結果を確認してから本実行
        GOOGLE_SA_KEY_FILE=/tmp/sa.json python3 furikomi/transcribe.py entries.json
        rm -f /tmp/sa.json

6. 結果を `ledger.json` の processed に記録
   （file_id → path, vendor, amount, month, cells, action）。
   保留になったものは `hold` として理由も書く。
7. `git add furikomi/ && git commit && git push -u origin claude/invoice-auto-transfer-1wdzx5`
8. 保留が出たときだけ利用者に報告する。全部きれいに入ったら黙ってコミットのみ。

依存: `pip install google-api-python-client google-auth`（コンテナに無ければ入れる）

## 請求書から取る金額（2026-08-25 7月分の全件突き合わせで確定）

**当月分の税込額を取る。繰越・前回請求残高は含めない。**

請求書によって欄の名前が違うが、指すものは同じ。

| 請求書の欄 | 例 |
|---|---|
| 今回御買上計 / 今回税込請求額 | ヴィーナスダイニング、鹿島食品 |
| 今回御買上額（内消費税） | ビーエム、室田石油、スギヤマ |
| 今回売上合計 | ダスキン |
| 今回ご請求高 / 当月ご請求高 | 山食、江東微生物研究所 |
| 合計 / 御請求金額 | ケミカルテクノロジー、リペアボックス、佐倉クレーン学校 |

**取ってはいけない欄**：「今回御請求額」「ご請求額」が繰越を含んでいることがある
（ビーエム 473,460 は繰越込み、当月分は 142,538）。前回請求残高・御入金額の欄が
あったら、そこは無視して当月分だけを見る。

### 例外・注意

- **前月に過入金があると「今回請求残高」が正**。鹿島食品もも焼き7月は税込請求額
  116,218 だが繰越 −71,067 があり、実際に払うのは残高 45,151。残高欄が
  税込請求額と違うときは残高を採る。
- **1枚に複数店舗が載る請求書は店別に分ける**（日本食研、片野商店は店ごとに別紙）。
  日本食研は「店計」が**税抜**なので、そのまま入れると消費税分が漏れる。
- **手書きで合計が書き込まれている請求書はその合計を採る**（複数枚を1回で払うため）。
  ガキゲン 81,460、居酒屋ドリーム 76,500 がこれ。ファイル1つに請求書が
  複数ページ入っている。
- **スキャン画像のPDFはテキスト抽出できない**（`fetch` が空文字を返す）。
  その場合は `download_link` → `curl` で落として PyMuPDF でページを画像化し、
  目視で読む。7月分は60件中35件が画像PDFだった。

      pip install pymupdf
      python3 -c "import pymupdf; d=pymupdf.open('x.pdf'); d[0].get_pixmap(dpi=150).save('x.png')"

## 運用メモ・ハマりどころ

- **月フォルダの請求書は後から増える**（2607月は23→60ファイルに増えた実績）。
  だから毎回全ファイルをリストして台帳と差分を取る。
- 支払いが済むとファイルは各店舗の `支払い済/` サブフォルダへ移動される。
  file_id 照合なので影響なし。
- **`支払い済/` の表記はこれで統一する**（利用者指示 2026-09-01）。
  い**あり**の「支払い済」。「支払済」ではない。
  2026-09-01 に 21期2608月の10店と 22期の全12か月×10店＝**計130フォルダ**を作成した。
  22期は 2609月〜2708月ぜんぶに入っているので、月が来ても作り足す必要はない。
  ★ただし古い月には「支払済」（いなし）が17個残っている
  （21期の 2509月・2510月の全店と 2511月の焼きたて屋）。
  統一したいと言われたらリネームする。いまは触っていない。
  ★店舗フォルダの階層は月によって違う。2606月までは `<月>/確認済/<店舗>/`、
  2607月からは `<月>/<店舗>/`。`支払い済/` はどちらでも店舗フォルダの直下。
- ファイル名の「〜8月末」「〜振替」「〜済」は支払い方法のヒント。
  「済」は支払い済みでも転記自体は行う（一覧は支払いの記録でもあるため）。
  ただし迷ったら保留。
- 本部フォルダでも中身が他店舗宛のことがある（pl/README.md ハマりどころ6・9）。
  請求書の宛名・内容を見て列を決め、フォルダ名だけで機械的に決めない。
- 1枚の請求書に複数店舗ぶんが載るもの（日本食研「ハナ・もも焼き・タコハイ」等）は
  店舗ごとに金額を分けて複数エントリにする。内訳が読めなければ保留。
- **2606月以前への後入れがあり得る。** 締まった月のフォルダに後から請求書が置かれることがある
  （2026-08-27にエスアイビーエス¥25,300が2606月/確認済/業務に追加された）。
  **月フォルダの原則どおり請求日の月のタブに入れる**（利用者判断 2026-08-27）。
  ファイル名の日付（例「８／２７」）は支払日であってタブの月ではない。
